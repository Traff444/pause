# ПАУЗА

Mobile-first PWA для постепенного сокращения курения: email/password Auth, offline-first
журнал, прозрачный расчёт интервалов и синхронизация с Supabase.

## Локальный запуск

```bash
cp .env.example .env.local
npm install
npm run dev
```

Для реального входа заполните в `.env.local` публичные `Project URL` и
`Publishable key` отдельного Supabase-проекта. Без них development-режим
по-прежнему позволяет пройти локальный визуальный сценарий; production-сборка
покажет понятное сообщение о незавершённой конфигурации.

Полная настройка: [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md).

## Как устроены данные

- IndexedDB хранит персональную локальную копию и позволяет отмечать сигареты
  без сети.
- После email-входа состояние и журнал синхронизируются с Supabase.
- Локальные записи разделены по Supabase user id: выход и вход другого
  пользователя не смешивают данные.
- Отмена сохраняется как tombstone (`deleted_at`), поэтому удалённая отметка не
  появится снова после синхронизации.

## Формула средней паузы

Для каждого локального календарного дня:

1. Берутся активные отметки и сортируются по времени.
2. Считаются интервалы между каждой парой соседних отметок.
3. Интервалы всех выбранных дней суммируются.
4. Сумма делится на число интервалов и округляется до минут.

Ночной переход между разными календарными днями и отменённые отметки не
учитываются. Та же формула реализована в SQL-view
`participant_smoking_timeline` и `participant_daily_summary`, поэтому в
Supabase видны как исходные интервалы, так и итог дня.

## Проверки

```bash
npm run check
supabase test db --local
```

Тесты покрывают расчёт базового ритма, интервалы, исключение ночных переходов,
таймер, экономию и сериализацию/слияние облачных данных. Отдельные pgTAP-тесты
проверяют SQL-формулу, исключение отменённых отметок и изоляцию пользователей
через RLS.

## Ручной тест

1. Создайте аккаунт по email и паролю или войдите в существующий.
2. Пройдите три шага онбординга.
3. Нажмите `ИДУ КУРИТЬ`, затем проверьте `ОТМЕНИТЬ`.
4. Откройте «Статистика» — до конца наблюдения там видны исходные интервалы и
   формула средней паузы.
5. Откройте настройки и проверьте статус синхронизации.
6. В Supabase откройте `participant_smoking_timeline`: там видны каждая
   сигарета, предыдущая отметка и интервал, использованный в формуле.
7. Откройте `participant_daily_summary` — количество и средняя пауза должны
   совпасть с таймлайном и приложением.

В development-настройках есть тестовые состояния для всех фаз программы. Этот
блок не попадает в production.

## Безопасность

- В браузере используется только публичный Publishable key.
- `service_role`, пароль базы и access token не входят в репозиторий и
  `VITE_*`-переменные.
- RLS разрешает пользователю читать и менять только строки со своим
  `auth.uid()`.
- Представление дневной сводки создано как `security_invoker`, поэтому не
  обходит RLS.
- Пароли обрабатываются только Supabase Auth и не попадают в таблицы приложения.
- На этапе пилота подтверждение email отключено, поэтому вход не зависит от SMTP.

## GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` собирает приложение для
`https://traff444.github.io/pause/`. Перед первым production-запуском добавьте
в GitHub Actions Variables:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

Утверждённые визуальные референсы находятся в `references/approved/`.
